# 탁구 기록장 — 배포 안내

대회·리그·레슨·연습을 달력에 기록하고, 예선/본선 성적과 피드백을 모아보는 1인용 웹사이트입니다.
정적 파일만으로 돌아가고, 기기 간 동기화는 Firebase Firestore를 씁니다.

```
index.html             화면
app.js                 전체 로직
config.js              ← 여기만 직접 수정합니다
firestore.rules        Firebase 보안 규칙 (콘솔에 붙여넣기)
manifest.webmanifest   홈 화면 추가용
icon.svg               아이콘
```

---

## 1단계 — 일단 그냥 띄워보기 (5분)

Firebase 없이도 동작합니다. 이 경우 기록은 **그 브라우저에만** 저장됩니다.

1. GitHub 가입 → 오른쪽 위 `+` → **New repository**
2. 이름은 아무거나 (예: `tt-log`), **Public** 선택 → Create
3. 저장소 화면에서 **uploading an existing file** 클릭 → 이 폴더의 파일 전부 드래그 → Commit
4. 상단 **Settings** → 왼쪽 **Pages** → Source를 `Deploy from a branch`,
   Branch를 `main` / `/ (root)` 로 두고 Save
5. 1~2분 뒤 `https://<깃허브아이디>.github.io/tt-log/` 로 접속

폰에서 이 주소를 열고 공유 → "홈 화면에 추가"를 하면 앱처럼 쓸 수 있습니다.

---

## 2단계 — 기기 간 동기화 켜기 (10분)

### 2-1. Firebase 프로젝트 만들기
1. https://console.firebase.google.com 접속 (구글 계정으로 로그인)
2. **프로젝트 추가** → 이름 입력 → Google 애널리틱스는 **사용 안 함** → 만들기

### 2-2. Firestore 데이터베이스 만들기
1. 왼쪽 메뉴 **빌드 → Firestore Database** → **데이터베이스 만들기**
2. 위치는 `asia-northeast3 (서울)` 추천
3. 시작 모드는 아무거나 선택 (어차피 다음 단계에서 규칙을 바꿉니다)

### 2-3. 보안 규칙 넣기
1. Firestore Database 화면 상단 **규칙** 탭
2. 내용을 전부 지우고 `firestore.rules` 파일의 내용을 붙여넣기 → **게시**

이 규칙은 "공간 코드가 8자 이상이면 읽기·쓰기 허용"입니다.
즉 **공간 코드를 아는 사람만** 내 기록에 접근할 수 있습니다. 코드를 길고 추측하기 어렵게 지으세요.

### 2-4. 웹 앱 등록하고 설정값 복사
1. 왼쪽 위 톱니바퀴 → **프로젝트 설정**
2. 아래로 내려 **내 앱** → 웹 아이콘 `</>` 클릭 → 앱 닉네임 입력 → 등록
3. 화면에 나오는 `const firebaseConfig = { ... }` 의 중괄호 안 값들을 복사

### 2-5. config.js 수정
`config.js` 를 열어 두 군데를 채웁니다.

```js
export const firebaseConfig = {
  apiKey: "AIza...",            // 2-4에서 복사한 값
  authDomain: "....firebaseapp.com",
  projectId: "my-tt-log",
  storageBucket: "....appspot.com",
  messagingSenderId: "123...",
  appId: "1:123...:web:..."
};

export const DEFAULT_SPACE = "kyunghee-tt-2026";   // 8자 이상, 나만 아는 문자열
```

GitHub 저장소에서 `config.js` 를 클릭 → 연필 아이콘 → 수정 → Commit.
1분쯤 뒤 사이트를 새로고침하면 헤더 표시가 **"동기화 중"** 으로 바뀝니다.

다른 기기에서도 같은 주소를 열고, 헤더의 동기화 버튼 → 공간 코드가 같은지 확인하면 끝입니다.

---

## 알아두면 좋은 것

- **apiKey는 비밀번호가 아닙니다.** 웹 Firebase 설정은 원래 공개되는 값이고, 실제 보호는 보안 규칙이 합니다. 그래서 공간 코드를 길게 잡는 게 중요합니다.
- **무료 한도**: Firestore 무료 플랜은 하루 읽기 5만 회 / 쓰기 2만 회입니다. 개인 기록용으로는 넘을 일이 없습니다.
- **백업**: 헤더의 동기화 버튼 → `JSON 내보내기` 로 전체 기록을 파일로 저장할 수 있고, `JSON 가져오기` 로 되돌릴 수 있습니다.
- **공간 코드를 바꾸면** 그 코드에 해당하는 기록으로 전환됩니다. 이전 기록이 지워지는 것은 아니고, 예전 코드를 다시 넣으면 돌아옵니다.
- **Vercel / Netlify** 를 써도 됩니다. 저장소를 연결하고 빌드 설정 없이 그대로 배포하면 됩니다.

## 기록 구조

| 종류 | 입력 항목 |
|---|---|
| 대회 | 참가 부수 · 예선 승-패/통과 여부 · 본선 라운드별 매치 스코어 · 잘된 점 · 보완할 점 |
| 리그 | 예선 승-패 · 본선 라운드별 매치 스코어 · **경기 과정 서술** · 잘된 점 · 보완할 점 |
| 레슨 | 훈련 내용 · 지적받은 점 · 잘된 점 |
| 연습 | 함께한 사람·장소 · 연습 내용 · 연습경기 전적 · 잘된 점 · 보완할 점 |

모든 기록은 **완료 / 예정** 상태를 가집니다. 예정은 달력에 점선으로 표시되고, 날짜가 지난 예정 기록을 열면 "기록 작성" 버튼이 나타납니다.
